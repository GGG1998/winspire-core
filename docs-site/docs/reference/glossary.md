# Glossary

## A

**API (Application Programming Interface)**
: Interface for programmatic access to a service.

**ADR (Architecture Decision Record)**
: Document that captures an important architectural decision.

**AsyncAPI**
: Specification for defining asynchronous APIs (events, messages).

## D

**Domain**
: A sphere of knowledge or business activity. In DDD, represents a specific business area.

**DDD (Domain-Driven Design)**
: Software design approach focusing on modeling based on business domain.

## E

**Event**
: Notification that something of interest has occurred in the system.

**Event-Driven Architecture**
: Architecture style where components communicate primarily through events.

## O

**OpenAPI**
: Specification for defining RESTful APIs (formerly Swagger).

## P

**Platform**
: Shared infrastructure and standards used across all domains.

## S

**Subdomain**
: A subdivision of a domain, representing a smaller business capability.

**Synchronous Communication**
: Request-response pattern where caller waits for response (e.g., REST API).

## A (continued)

**Asynchronous Communication**
: Fire-and-forget pattern where caller doesn't wait (e.g., events).
